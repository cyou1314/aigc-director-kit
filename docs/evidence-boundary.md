# Evidence boundary

这个项目刻意把三层证据分开：

1. **合同验证**：JSON 字段、数值范围、关键帧排序和镜头交接可被程序检查；
2. **运行时验证**：Blender 或其他适配器是否能执行计划，需要独立测试；
3. **成片 QC**：生成视频是否符合分镜、角色、动作、口型和连续性，需要真实成片和明确的 QC 任务。

`validate-plan` 只证明第一层。`compile-action` 只证明请求命中了动作目录中的已知描述。它们都不证明：

- 真实动作数据存在或许可证允许再分发；
- Blender 运行时能无穿插、无脚滑地执行动作；
- Seedance 或其他视频模型会完整服从合同；
- 最终画面达到导演验收标准。

适配器应在自己的仓库或用户项目中保存真实资产、许可证和运行报告，并把路径以接口参数传给本项目，而不是把私人资产打进核心包。
